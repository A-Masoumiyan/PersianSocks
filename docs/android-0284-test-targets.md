# Android 0.28.4 — test destinations and more TLS candidates

Seven additional HTTPS candidate feeds were retrieved successfully: Databay (1,932 rows), Zaeem20 (971), SevenworksDev (7,322), ShiftyTR (13), zloi-user (1,007), Proxio (7,171) and hproxy (3,735). TLS candidate feeds increase from 3 to 10. These are untrusted candidate inputs, not proof that the proxy hop supports certificate-valid TLS. Many publishers use HTTPS to describe end-to-end HTTPS over HTTP CONNECT (Moleway explicitly documents this: https://github.com/Moleway/Free-Proxy-List). Every HTTPS candidate still goes through the existing strict proxy-hop TLS and destination TLS checks; no certificate/authentication checks are relaxed. Counts are a retrieval snapshot and include overlap, not guaranteed usable proxies.

The scan section has ping and speed destination actions, also reachable through the scan menu. Ping can stay automatic or select exactly one configured test domain. Full scans still verify all configured services and take the ping from the chosen domain. Ping-only scans contact only that HTTPS endpoint, mark only that target checked/passed and never claim other services or UDP. Main and service auto-scans capture the profile. Individual/saved ping retests use the selected target. Checkpoint fingerprints include the profile, so changing it cannot resume a different test as the old one. Prior ping values from other domains are excluded from the chosen-domain ping limit/ranking and shown as untested for that destination; their provenance stays in details.

Speed configuration accepts an exact HTTPS file URL on a configured test hostname. Single, filtered and saved batch tests use that file through each explicitly selected proxy. The scan menu can start speed testing the filtered successful results; downloads are not automatically run against every unverified catalog entry. The existing batch consumption confirmation and per-test 20 MB/20-second limits remain. Custom URLs are not rewritten with a query and never fall back to Cloudflare/OVH or another domain. Credentials, non-HTTPS, unexpected ports, fragments and unconfigured hosts are rejected. HTML or less than 256 KB is not accepted as a speed sample. Successful results and failed-attempt destinations have separate metadata; speeds from a different target cannot silently enter the current ranking. Clearing custom selection returns to the existing default download behavior.

Validation: full host suite passed, including 37 new configured-target checks using real local proxy sockets and TLS across SOCKS5/HTTP/HTTPS. The checks cover target isolation, per-service masks, custom download path/query, small/HTML samples, certificate rejection, captured profiles, checkpoint incompatibility and persisted ping provenance. Offline APK build, signature/integrity audit and 540 bilingual resource checks passed. Real phone UI and Iranian network/proxy availability remain untested.
