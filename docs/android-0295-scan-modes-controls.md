# Android 0.29.5 / versionCode 44

The main scan control is Play/Pause. With an unfinished compatible checkpoint, Play resumes that checkpoint without asking for another mode. With no pending scan, Play opens a two-item Fast/Deep dialog; the separate restart button always opens that dialog for a fresh catalog scan. Mode selection is not in the sidebar. The old scan dropdown and its three misplaced extras are removed. Existing ping/speed target controls remain in the sidebar and filtered-result speed testing stays in the results toolbar. Full healthy-result rescanning is available as a sidebar tool.

The checkpoint's existing slow boolean freezes the chosen mode: false=Fast, true=Deep. It is already stored in both legacy JSON and journal headers, so relaunch/resume preserves the chosen mode. The user preference records the last chosen mode for automatic scanning; changing it cannot alter the frozen pending scan. No schema or checkpoint format change is required.

Fast starts with 24 concurrent tests, adapts between 6 and 36; Deep starts with 4 and adapts between 1 and 6. Foreground ceilings are 36/6, background 18/3 and VPN setup 6/1. The configured capacity ratio is six across those states. Both modes perform the same actual protocol, certificate-verified HTTPS, service and real UDP checks; fast never converts an untested service into success. Fast uses the existing adaptive normal deadlines; Deep gives each attempt the existing 6/9/20-second connect/read/total budgets. Actual throughput depends on endpoints and network/CPU limits; a universal sixfold wall-clock guarantee is not possible.

Total/checked counters have vector icons and remain physically left of scan controls in both languages. They use the original pending scan's denominator, so catalog pruning does not change progress mid-scan. Pause retains its progress bar; completed counts survive relaunch until a new catalog is received or a new scan starts. Favorites, source priority, transport protocols, original signature, bundled libraries and 512 MiB update support remain unchanged.

The controlled 144-endpoint fixture (150 ms synthetic delay each) completed in 956 ms Fast and 5520 ms Deep (5.77x); this measures host scheduling rather than phone/network throughput. The complete host suites, 48 mode checks, six concurrency cohorts, 21 Android tests and localization checks passed; lint had zero errors and the signed APK audit passed. Validation results are recorded in verification.txt and the release. No physical Android phone is attached to this environment.
